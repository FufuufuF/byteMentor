# Byte Mentor 产品计划（已确定部分）

## 1. 文档原则

本文档只记录已经明确达成共识的内容。

尚未完全确定的内容暂不写入计划文档，包括但不限于：

- 前端 UI 设计
- 具体数据模型
- 具体知识图谱结构
- 具体评分规则
- 具体复习机制
- 具体岗位模板或课程模板

当前阶段先保持文档干净，避免把还在讨论中的想法固化成计划。

## 2. 产品核心目标

Byte Mentor 面向计算机领域的知识学习。

产品重点不是重新做一个“AI 教学助手”。在当前通用模型能力下，只要给合适的 prompt 或 skill，AI 的讲解能力已经基本可用。

Byte Mentor 更核心的目标是：

> 在学习过程中沉淀用户的知识体系，让 AI 在后续教学中知道用户当前的知识状态。

这里的“知识状态”至少包括：

- 用户学过哪些知识
- 用户正在学习哪些知识
- 用户对哪些知识理解不清
- 用户在哪些地方暴露过误解或盲区
- AI 后续教学时应该参考哪些历史学习痕迹

## 3. 当前讨论优先级

当前优先考虑 agent / 后端形态。

暂时不讨论前端 UI 的具体设计。

原因是：产品的核心价值来自学习过程中如何沉淀知识、如何让 AI 使用这些沉淀，而不是来自第一版界面形态。

## 4. MVP 最粗链路

当前已经确定的 MVP 链路是：

1. 用户向 agent 提出一个需要学习的领域或知识模块。
2. 例如：`JavaScript 的异步机制`、`计算机网络中的 TCP`、`操作系统中的进程与线程`。
3. agent 开始围绕该知识模块进行教学。
4. 教学过程中，agent 需要持续维护两层笔记。
5. 学习结束后，这些笔记应该能被后续学习继续使用。

这条链路的重点是：

> 用户不是单次向 AI 提问，而是在一个持续学习系统中逐步沉淀自己的知识体系。

## 5. 两层笔记

教学过程中需要维护两层笔记。

### 5.1 用户读的笔记

这一层笔记面向用户自己。

它的作用是帮助用户在学习后回顾知识。

目前只确定它应该存在，具体格式还没有确定。

### 5.2 AI 读的笔记

这一层笔记面向 agent。

它的作用是进入知识图谱、知识库或其他长期记忆结构，让 AI 后续能够理解用户当前的知识体系。

这一层是产品的核心价值之一。

目前只确定它应该存在，并且应该服务于后续教学。具体结构、字段、存储方式和更新规则还没有确定。

## 6. 当前未确定事项

以下内容需要继续讨论，暂不写成正式计划：

- agent 如何判断一个知识模块的边界
- 教学过程中什么时候更新笔记
- 用户读的笔记应该长什么样
- AI 读的笔记应该如何进入知识图谱
- 知识图谱是否必须存在，还是可以先用更简单的知识库形式
- agent 如何在下一次教学前读取和使用历史笔记
- 是否需要复述、追问、测验或模拟面试
- 是否需要评分或掌握度判断
- 第一版是否需要固定模板
